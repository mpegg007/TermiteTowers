# Apps in this repository, and the paths each one owns.
#
# This is the boundary that packages draw from. A path belongs to AT MOST ONE app:
# `coverage` reports both paths under no app and paths claimed twice, because an
# ambiguous owner is how a file gets promoted by nobody and deleted by accident.
#
# Grouping rules, from wiki/service-taxonomy.md:
#   - a SERVICE has a tenant, a public identity, owned data and an independent
#     lifecycle. It gets its own app.
#   - platform concerns (dns, dhcp, nginx, docker, systemd, backups, logrotate,
#     certbot, log collector) are split by concern rather than lumped into one "infra"
#     app, because they promote separately and several contain privileged paths.
#   - tooling that exists to develop the estate (scripts, util, setup, promote, tests,
#     git-automation) is owned, but is not deployed to a tier's run area.
#   - repo plumbing (.github, .clinerules, root config files, host start/stop scripts)
#     is owned too. It is not "nobody's", it is an app whose lifecycle is the repo.
#
# Format:  <app> : <prefix> [prefix...]
# A trailing '/' means a path prefix; a full path means exactly that path.
#
# Symlinks are deliberately absent: they are never promotable, so they are never
# owned by anything.
