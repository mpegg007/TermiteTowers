# Paths whose PRESENCE is behaviour, not content.
#
# A workflow on the target branch fires on the next push to it. An installed systemd
# unit runs. An enabled vhost listens. A logrotate file is picked up on the next
# rotation. Promoting one of these can redeploy, restart or expose something with no
# content change at all, so `build` refuses unless the package entry carries an
# explicit `!`.
#
# The check is bidirectional: a missing `!` fails, and a `!` on a path that is NOT in
# this file also fails. That keeps the human's approval and the machine's
# classification from drifting apart in either direction.
#
# Matching: a trailing '/' means a path prefix.
#
# See docs/design/promotion-model.md section 9.
